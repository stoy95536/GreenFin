# GreenFin Rules Specification

> 所有規則均為 Demo / PoC 初始參數。正式上線前須經場域 PoC、專家、金融機構與真實資料分布校準。

## 1. Rule Set

Current:

```text
GREENFIN_DEMO_V1
```

所有計算需保存：
- rule_version
- calculated_at
- input_evidence_ids
- calculation_trace

歷史結果不得因規則更新而被無聲覆蓋。

## 2. Source Levels

| 等級 | 定義 | 例子 | Demo 處理 |
|---|---|---|---|
| V3 | 官方／合作系統直接核驗 | 官方查詢、有效 QR、合作 API | 完整認列 |
| V2 | 可查核第三方文件 | 認證、聯單、發票、農會證明 | 完整認列 |
| V1 | 自行提交且部分佐證 | 照片、手寫紀錄、自填日誌 | 部分認列或待補 |
| V0 | 無法使用或確認異常 | 模糊、過期、重複、矛盾 | 不認列、轉覆核 |

> V1 的「部分認列比例」屬待實作的 Demo Config，不得在未確認時自行宣稱為正式標準。

## 3. 經驗值

四構面：
- 減量
- 增匯
- 循環
- 綠色治理

每構面年度上限：250  
總上限：1000

基礎行為：

| 行為層級 | 基礎值 |
|---|---:|
| 單次基礎行為 | 20 |
| 持續性措施 | 50 |
| 正式驗證／重大投入 | 100 |

公式：

```text
單筆有效經驗值 = 行為基礎經驗值 × 來源認列比例
```

同類行為不得超過年度上限。

## 4. 四大分析指標

### 資料完整度

Demo V1：

| 等級 | 範圍 |
|---|---|
| L1 | 0–39% |
| L2 | 40–59% |
| L3 | 60–79% |
| L4 | 80–94% |
| L5 | 95–100% 且無核心必要缺件 |

概念權重：
- 核心必要 = 3
- 重要佐證 = 2
- 補充資料 = 1

### 資料可信度

Demo V1：

| 等級 | 範圍 |
|---|---|
| L1 | 0–19 |
| L2 | 20–39 |
| L3 | 40–59 |
| L4 | 60–79 |
| L5 | 80–100 |

依據包含：
- V0–V3
- 效期
- 跨資料一致性
- 重複
- 異常
- 可追溯程度

### 經營成熟度

依據：
- 紀錄期間
- 資料種類
- 更新持續性
- 缺漏月份
- 交叉核對

### 綠色成熟度

依據：
- 經驗值
- 構面廣度
- 持續期間
- V2/V3 比例
- 異常

綠色成熟度可以參考經驗值，但不得等於經驗值，更不得轉成信用分數。

## 5. Data Health

狀態：
- GREEN：目前可供參考
- YELLOW：可參考但需補強
- RED：目前不宜使用
- GRAY：未提供、未核驗、不適用或未授權

判定優先序：

```text
1. 不適用／未授權 → GRAY
2. 重大異常／核心缺件 → RED
3. 一般缺漏／即將到期／待確認 → YELLOW
4. 其餘符合 → GREEN
```

每個 Data Health 結果必須包含：
- status
- reasons[]
- actions[]
- affected_evidence_ids
- rule_version

## 6. 禁止推論

任何規則都不得產生：
- 核貸機率
- 違約機率
- 額度
- 利率
- 信用總分
